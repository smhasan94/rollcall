# rollcall v0.1.0

The first release of rollcall: CRA-oriented CycloneDX 1.6 SBOMs from firmware build metadata,
for Zephyr first, with Cargo, ESP-IDF and PlatformIO alongside, plus VEX, scanning, a
readiness report and a GitHub Action. The full list of changes is in
[CHANGELOG.md](../../CHANGELOG.md#010---2026-10-05); the docs are at
<https://smhasan94.github.io/rollcall/>.

## Output format: CycloneDX 1.6 only

rollcall writes **CycloneDX 1.6 JSON only**. SPDX export is deferred to 1.0 or until someone
needs it, tracked in [#37](https://github.com/smhasan94/rollcall/issues/37). If you need SPDX
today, convert with the CycloneDX CLI:

```sh
cyclonedx convert --input-file sbom.cdx.json --output-file sbom.spdx.json --output-format spdxjson
```

The conversion is **lossy**: rollcall's `rollcall:` properties, component evidence, the nested
hierarchy (product, images, subsystems) and VEX may not survive it. Check the result, and keep
the CycloneDX document as the record.

## Highlights

- **Zephyr**: `rollcall generate` reads `west spdx`, `west list`, Kconfig `.config`, the link
  map and `build_info.yml`; splits the `zephyr` component into the subsystems the build
  enabled and linked; and makes one product of a sysbuild build (MCUboot and the application).
- **Identifiers**: an identifier database of Zephyr modules with fork-to-upstream version
  tables, so modules carry upstream purls and, where NVD lists them, CPEs.
- **More ecosystems**: Cargo (`cargo metadata` and `cargo auditable`), ESP-IDF (with its
  subsystem split and Espressif blobs) and PlatformIO, and `rollcall generate DIR` tells them
  apart.
- **Merge**: bootloader, application and binary blobs in one product hierarchy.
- **VEX**: a rule format with Kconfig evidence, a starter rule pack, CycloneDX VEX and OpenVEX
  output, optional signing.
- **Scan and validate**: `rollcall scan` (grype and osv-scanner, normalised, with exit codes
  for CI), `rollcall validate` against the CycloneDX 1.6 schema and the CISA 2026 and CRA
  profiles, and a readiness report in Markdown and JSON.
- **CSAF 2.0** export for vulnerability handoff (cra-clock).
- **GitHub Action** with a pull-request comment, a diff against the base branch and a gate on
  new findings.

## Install

- Release binaries: `rollcall-v0.1.0-linux-amd64.tar.gz`, `rollcall-v0.1.0-linux-arm64.tar.gz`,
  `rollcall-v0.1.0-darwin-universal.tar.gz` and `rollcall-v0.1.0-windows-amd64.zip`, with
  `SHA256SUMS` (check with `sha256sum --check --ignore-missing SHA256SUMS`) and build provenance
  attestations (`gh attestation verify <file> --repo smhasan94/rollcall`). Each archive holds one
  directory, `rollcall-v0.1.0-<platform>/`, with the `rollcall` binary (`rollcall.exe` on
  Windows), `LICENSE` and `README.md`.
- `cargo install rollcall --locked` (Rust 1.91 or newer).
- `pip install rollcall==0.1.0`: a small wrapper that downloads the release binary on first run
  and checks it against the SHA-256 recorded in the package.
- The Action: `uses: smhasan94/rollcall/action@v0.1.0` with `rollcall-version: v0.1.0`.

The [quickstart](../quickstart.md) goes from a Zephyr build directory to a validated SBOM.

## Known limitations

- **Zephyr SBOMs do not pass the CISA 2026 and CRA profiles yet.** They are valid CycloneDX
  1.6, but the product and images have no version, supplier, identifier or hash, and
  components built from source have no hash
  ([#14](https://github.com/smhasan94/rollcall/issues/14); see
  [What west spdx leaves out](../zephyr-gaps.md#gap-5-cyclonedx)). `--product NAME@VERSION`
  names and versions the product.
- **Zephyr inputs**: on Zephyr v4.4, each image's build directory must be prepared with
  `west spdx --init` before the build, and every image, MCUboot included, needs
  `CONFIG_BUILD_OUTPUT_META` ([Zephyr gap analysis](../zephyr-gaps.md#rollcall-as-the-companion)).
- **Scanning Zephyr SBOMs**: osv-scanner finds nothing for Zephyr modules, and grype skips the
  `zephyr` component itself (type `operating-system`); see [Scanning](../scan.md#known-limitations).
- **ESP-IDF**: what is linked comes from the GNU ld map (no ELF analysis); only esp32 on
  ESP-IDF v5.5.1 is covered by a fixture; see [ESP-IDF](../esp-idf.md#limitations).
- **PlatformIO**: one environment per SBOM; the framework is one component, and the ESP-IDF
  libraries precompiled into Arduino-ESP32 are not split out
  ([#35](https://github.com/smhasan94/rollcall/issues/35)); built-in and project-local
  libraries are not listed; no hashes. **Arduino-ESP32 2.0.17**, the newest release
  PlatformIO's official `espressif32` platform ships, **has open CVEs**, which rollcall
  reports; see [PlatformIO](../platformio.md#limitations).
- **CSAF export** writes each document as a first revision; revision history across updates is
  [#33](https://github.com/smhasan94/rollcall/issues/33).
- **`rollcall assay`** (the CBOM) is not implemented in this release.
